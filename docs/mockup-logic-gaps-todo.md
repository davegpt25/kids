# 키즈루트 목업 — 논리 단절 / 놓친 연결 TODO

`kids/index.html` 학부모·관리자·원장 포털 간 데이터 흐름을 점검하며 발견한 항목들. (2026-06-26 검토)

## 1. "내 스케줄"에 등록된 학원 정보가 스냅샷이라 갱신되지 않음
- `urToggleSchedule` ([kids/index.html:7808](../index.html#L7808))가 학원 추가 시 `name/color/times`를 그 시점 값으로 복사 저장.
- 이후 원장이 `krapSaveTt`로 시간표를 바꿔도(`KR_SYNC.set`) 이미 등록된 학부모의 "내 스케줄"·"하원 여정 라인"은 옛 시간 그대로 노출됨.
- 검색 목록(`KR_SYNC.getMergedAcademies()`)은 최신인데 내 스케줄은 과거 데이터 — 모순.

## 2. "학원 시간표 변경 알림"이 마케팅 카피로만 존재
- 가격표 비교([kids/index.html:1134](../index.html#L1134), [3463](../index.html#L3463))에서 "학원 시간표 변경 알림 ✓", "수업 종료 즉시" 알림을 강조.
- 실제로 원장이 시간표를 바꿨을 때 학부모에게 토스트/푸시가 가는 로직 없음.
- 하원 알림(`uj-push-badge`)의 이동시간도 `academyId % 5` 기반 가짜 난수이며, "수업 종료" 시각 기반 트리거 시뮬레이션 없음.

## 3. 알림 설정이 두 군데로 분리되어 서로 무관
- "내 정보" 탭 마스터 알림 카드(`kr_notif_prefs`: 공석/리마인더/뉴스) — [kids/index.html:8550](../index.html#L8550)
- "스케줄" 탭 학원별 하원 알림(`kr_push_prefs`) — [kids/index.html:7894](../index.html#L7894)
- 예: "스케줄 리마인더" 토글을 꺼도 하원 여정 라인의 푸시 배지는 그대로 ON.

## 4. 원장/관리자 쪽엔 하원 알림 기능 자체가 보이지 않음
- 원장 포털(`krap*`), 관리자 대시보드(`admin*`) 어디에도 "하원 알림 사용 현황/발송 로그"가 없음.
- 학부모 전용 기능으로 고립 — 운영자가 기능 사용률을 확인할 지점이 없음.

## 5. 여정 순서가 등록 순서를 그대로 사용
- `urRenderJourney` ([kids/index.html:7900](../index.html#L7900))의 `ordered = schedule.slice()`가 등록 순서를 이동 경로 순서로 가정.
- 학부모가 등록한 순서와 실제 그날 수업 시간 순서가 다르면 여정 라인이 실제 동선과 안 맞을 수 있음.

## 6. 백엔드(kidsroute-backend) 배포 및 정적 목업과의 실연동
- `AcademyReport`/`isActive` 신고 처리 파이프라인을 백엔드에 만들었지만, 배포된 곳이 없어서 정적 목업(`kids/index.html`, GH Pages)의 🚩 신고 버튼은 여전히 `localStorage`에만 기록됨 — 실제 관리자가 볼 방법이 없음.
- 필요 작업: ① 백엔드를 접근 가능한 주소에 배포, ② `kids/index.html`에 API_BASE_URL 설정 추가해 `urReportAcademyPrompt` 등이 실제로 `POST /academies/:id/reports`를 호출하도록 연결.
- 로컬호스트 주소로는 방문자 브라우저에서 호출 불가하므로 배포가 선행 조건.

## 7. 신고 검토에 role 기반 권한 제어가 없음
- `GET /academies/reports/pending`, `PATCH /academies/reports/:id/resolve` ([kidsroute-backend/src/academy/academy.controller.ts](../../kidsroute-backend/src/academy/academy.controller.ts))가 일반 로그인 사용자 누구나 접근 가능 — admin role 시스템이 아직 없어서 임시로 JWT 인증만 걸어둠.
- 별도 관리자 role/가드가 생기면 이 두 엔드포인트부터 교체할 것.

## 8. `findNearby`의 time_slots JOIN 컬럼명 의심
- [kidsroute-backend/src/academy/academy.service.ts](../../kidsroute-backend/src/academy/academy.service.ts)의 raw SQL이 `ts.academy_id`(snake_case)를 참조하는데, TypeORM 기본 네이밍 전략이면 실제 컬럼은 `academyId`(camelCase)일 가능성이 높음.
- 지금까지 테스트가 전부 `repository.query()`를 mock해서 실행돼서 실제 DB로 한 번도 검증된 적이 없는 코드 — 실제 DB 연결 시 가장 먼저 확인해야 함.

## 9. 네이버 오픈API 출처 표시 의무 — 법률 검토 필요
- 학원 목록에 "출처: 네이버 지도 공개 정보" 문구를 기본값으로 넣어뒀지만, 정확한 약관 조항(재배포 범위, 표시 방식 요건)은 변호사 검토가 필요함. 데모 범위를 넘어 정식 서비스로 확장하기 전에 확인할 것.

## 10. 연령 필터가 단일선택이라 1차 타겟(유아+초등5학년)을 한 번에 표현 못 함
- 1차 타겟은 "유아~초등5학년"인데 `urAgeFilterRow`([kids/index.html](../index.html))의 칩은 하나만 선택 가능 — "초등"만 기본 선택하면 유아 학원이 빠져서 기본값을 결국 "전체"로 되돌림.
- 다중선택(또는 "유아+초등" 묶음 칩)을 지원하면 1차 타겟을 정확히 기본값으로 노출할 수 있음.

## 11. 서울 학원 데이터가 구(區) 단위로만 수집되어 동 단위보다 정밀도 낮음
- 네이버 지역검색이 좌표/반경 파라미터를 지원하지 않아 "동네이름+과목"으로 검색하는데, 전국 행정동 목록(427개)을 안전하게 확보 못 해서 일단 25개 구 단위(200건 검색)로 921개를 모음.
- 구 단위라 한 구 안에서도 특정 동에 검색이 몰리거나 빠질 수 있음. 필요한 동이 생기면(예: 반포동·서대문 사례처럼) 그 동만 추가로 보강하는 식으로 점진 개선.
